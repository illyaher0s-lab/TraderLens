## 用户可见闭环与验收

用户从 Gate001 冻结规则实际生成的历史测试信号进入测试 Action Plan，再人工确认模拟买入、观察持仓、人工模拟卖出，并看到逐日账户/NAV、确定性 P&L 与复盘。确定性回放和用户确认事件分开保存；来源可追溯，缺失字段显式显示。

1. **逐腿一致：**7 条成交腿逐笔对照独立保存审计的日期、数量、价格、费用与净现金流。4 条入场 raw provenance 与 3 条退出 derived provenance 如实区分；不得伪造原始信号来源。
2. **账户一致：**13 条去重分红、其中 9 条持仓权益；3 个闭环周期与 1 个期末未平仓周期的 P&L；现金、应收、市值与逐日 NAV 对齐独立保存的审计结果。报告的分红展示更正不是直接 oracle。
3. **因果边界：**任何读取都按 `as_of` 截断；请求未来日期或越过 `2020-12-31` 必须在调用数据读取器之前拒绝。用合成探针断言拒绝发生且读取器未被调用，不访问真实 Holdout。数值相同不单独证明无未来函数；差异先分类根因，不先归因数据泄露。
4. **账本与展示边界：**自动化验证测试标记从来源到复盘不可丢失、客户端不能改为正式来源，测试记录不能出现在正式账户查询；页面不误称真实建议。新增的是产品验证记录，不冒充新 Alpha 研究，不改变原 research=1 / technical=4 / synthetic=3 计数。

## 实施顺序

1. **第一项：Replay 来源与账本隔离 RED→GREEN。**当前 inspected contracts 没有 `test_only` 模式。仅新增/连接后端来源判定与测试账路由；用失败测试证明客户端不能创建正式来源、测试写入不进入正式账本/查询。此任务只解决来源与隔离，不改 Action Plan ID 绑定、不改费用或 P&L。
2. **独立任务：沿证据链传播来源标记。**按既有 contracts/callers/test，为测试 Action Plan、成交、持仓、复盘保存和返回同一服务端来源标记；验证任何中间环节丢标都会失败。第一项完成后再做。
3. **独立任务：绑定真实 Action Plan。**workbench 买入路径当前生成临时 signal/plan ID，卖出复盘将 Action Plan 记为缺失；单独把生成的测试 Action Plan ID 贯穿模拟买入、持仓、卖出与复盘，并用聚焦测试验证。这不与来源隔离同 patch。
4. **历史信号与因果门。**仅从冻结快照按逐日 `as_of` 生成信号；合成探针验证未来读取和超过 `2020-12-31` 的读取在数据源调用前被拒绝。不接外部行情/API，不读取真实 Holdout。
5. **独立账户核算任务。**将冻结费用、分红和现金事件纳入逐日账本/P&L/复盘，与独立审计对齐；workbench helper 当前 `fees=None`，需作为本任务单独修复，不并入前述来源、ID 或 as-of patch。
6. **界面与整条路径验收。**用户确认模拟买卖后查看持仓、P&L 与复盘；界面明确标注历史测试信号。每个任务先读目标 contracts/callers/tests、保存目标恢复点、写 RED 测试；先 compile/import，再跑聚焦测试和对应用户路径。新独立主线 blocker 出现时停止并只报一个 blocker；最终做独立验收及文件/账本哈希核对。

## 未来策略目标与 Discovery 预算（已确认；不属于 Replay-001 / Gate001 规则）

- **持仓与止损：**平均持仓 5–10 个交易日，硬上限 21 个交易日；达到期限后次日开盘强制卖出。单笔止损 3%，须事前冻结。止损和期限规则不保证实际亏损不超过 3%，也不保证到期成交；继续遵守 T+1、停牌、涨跌停与费用约束，未成交或超限如实报告。
- **频率：**每年 15–25 笔完整买卖（约平均每月 1–2 笔）；不强制每月交易，不为达到频率制造信号或交易。
- **研究表现目标：**研究期成本后账户最大回撤不超过 12%，净 CAGR 及格线约 6%；净 CAGR 约 8% 为好结果，10% 以上仅作较好表现参考，不是收益硬封顶或自动 reject 条件。双倍成本压力情景净 CAGR 及格线为 2%，并报告相对主情景下降的百分点。账户 MDD 按净值历史高点到其后低点计算，不按初始本金固定计算：例如净值高点为 10 万元时，12% 回撤对应 8.8 万元；若后来高点升至 12 万元，对应阈值为 10.56 万元。模拟盘账户回撤超过 20% 时暂停策略。
- **Discovery 上限：**最多 5 个候选、最多 6 周；六周从未来 Discovery 正式启动并记录起止时间时开始计，不从 Replay 或文档建设开始。整个 Discovery 期间不访问留出数据；达到期限或候选上限仍无通过候选即停止搜索。候选按独立规格 hash 计数；影响信号、成交或参数的修改后重新看结果，计为新候选。统计或单元测试修复不冒充新研究，但须如实记录。
- **使用边界：**系统保留决策辅助用途。银行存款或被动持有只作为用户考虑的资金选择记录，系统不执行资产配置、资金转移或交易。
- **未来候选的事前冻结项：**任何候选在首次查看收益前，先明确止损触发价格口径、持仓交易日计数起点、止损/到期卖出遇停牌或涨跌停时的处理、样本统计年份定义，以及双倍成本压力中的具体成本项与加倍方法。本项须按逐笔实际仓位、成交、最低佣金、滑点、价位规则与税费等确定性重算；不得将 Gate ETF 成本直接套用于所有未来个股。用户提供的 0.16% 往返成本×每年 15–25 笔推算 2.4–4 个百分点拖累仅作粗算，不作为确定年度净 CAGR 或交易次数上限。主情景“约 6%”的精确裁决阈值和容差须在未来 Discovery 首次查看收益前冻结；本阶段不擅定精确阈值或容差。未冻结前不得查看候选收益。

以上目标仅约束未来候选与 Discovery，不改变 Gate001 V1 的规则或历史结果；本阶段不启动 Discovery。
