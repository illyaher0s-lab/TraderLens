# Tushare Frozen Sample Generation Guide

## Overview

This guide explains how to generate and use frozen Tushare data snapshots for reproducible backtests.

**Critical**: CI and tests ONLY read frozen snapshots. Never call Tushare API in automated tests.

---

## Prerequisites

1. **Tushare API Token**
   - Register at https://tushare.pro/
   - Get your token from user center
   - Set environment variable:
     ```bash
     export TUSHARE_TOKEN="your_token_here"
     ```

2. **Python Environment**
   - Activate venv: `source .venv/Scripts/activate` (Windows Git Bash)
   - Install dependencies: `pip install -r requirements.txt`

---

## Generate Frozen Sample

**Run once manually** to create frozen snapshot:

```bash
cd /d/Codex/TraderLens
source .venv/Scripts/activate
python backend/scripts/generate_sample_snapshot.py
```

**Output**:
- Snapshot saved to: `data/tushare_snapshots/`
- Contains:
  - 10 A-share stocks (major indices constituents)
  - 30 trading days (Dec 2023)
  - Daily bars (OHLCV + adj_factor)
  - Daily status (ST, suspended, limit up/down)
  - Metadata + snapshot hash

**Commit frozen sample** to git:
```bash
git add data/tushare_snapshots/
git commit -m "Add frozen Tushare sample for M3.4"
```

---

## Run Backtest with Frozen Sample

```bash
python backend/scripts/run_a_share_backtest.py \
    --snapshot-dir data/tushare_snapshots \
    --strategy examples/strategies/m3_4_tushare_real_data.yaml \
    --output output/m3_4_backtest \
    --initial-capital 100000
```

**Inputs**:
- `--snapshot-dir`: Path to frozen snapshot (NO API calls)
- `--strategy`: Strategy YAML file
- `--output`: Output directory for results
- `--initial-capital`: Starting capital (default: 100000)

**Outputs**:
- `metrics.json`: Performance metrics
- `trades.csv`: All trades with costs
- `round_trips.csv`: Matched buy-sell pairs
- `equity_curve.csv`: Daily portfolio values

## Reproducibility Guarantee

**Same snapshot + same strategy = same result**

Verified by `tests/test_tushare_reproducibility.py`:
- ✅ Two runs produce identical final_capital
- ✅ Two runs produce identical total_return  
- ✅ Export files have identical content hash (excluding timestamps)

**Non-deterministic fields** (excluded from hash):
- `created_at`, `runtime_seconds`, `export_time`
- Absolute file paths
- Process IDs

## CI/Test Usage

**Tests NEVER call Tushare API**:
- ✅ Use mock client for unit tests
- ✅ Read frozen sample for integration tests
- ✅ Skip real API tests in CI (no token)

**Frozen sample location**:
- Production: `data/tushare_snapshots/` (committed to git)
- Tests: `tests/` (generated by mock in setUp)

## Snapshot Structure

```
data/tushare_snapshots/
├── metadata/
│   ├── manifest.json          # Snapshot metadata + hash
│   ├── stock_list.json        # Symbol list + basic info
│   └── trade_calendar.json    # Trading dates
└── data/
    ├── 600519.SH_daily.parquet    # Daily bars
    ├── 600519.SH_status.parquet   # Daily status
    ├── 000001.SZ_daily.parquet
    └── ...
```

**manifest.json**:
```json
{
  "snapshot_id": "10stocks_30days",
  "snapshot_hash": "a1b2c3d4e5f6g7h8",
  "generated_at": "2026-06-22T12:00:00",
  "source": "tushare",
  "is_frozen": true,
  "symbol_count": 10,
  "trading_days": 30,
  "date_range_start": "2023-12-01",
  "date_range_end": "2023-12-29"
}
```

## Snapshot Validation

TushareDataSource validates snapshot on load:
- ✅ manifest.json exists
- ✅ stock_list.json exists
- ✅ trade_calendar.json exists
- ✅ All Parquet files exist
- ✅ Snapshot hash matches manifest

Run validation manually:
```python
from backend.app.tushare.config import TushareConfig
from backend.app.tushare.tushare_data_source import TushareDataSource

config = TushareConfig.from_env()
ds = TushareDataSource(config)
result = ds.validate()
print(result.status)  # "pass" or "failed"
```

## Troubleshooting

**Error: "Snapshot metadata not found"**
- Run `generate_sample_snapshot.py` first
- Check `data/tushare_snapshots/metadata/manifest.json` exists

**Error: "TUSHARE_TOKEN not set"**
- Set environment variable: `export TUSHARE_TOKEN="your_token"`
- Or pass token directly: `TushareConfig(token="your_token")`

**Error: "Symbol not available in data source"**
- Strategy YAML references symbol not in snapshot
- Regenerate snapshot with required symbols

## Best Practices

1. **Never commit real API token** to git
2. **Always commit frozen snapshots** for reproducibility
3. **Regenerate snapshots** when data requirements change
4. **Verify reproducibility** after regenerating snapshot
5. **Document snapshot generation date** in commit message
